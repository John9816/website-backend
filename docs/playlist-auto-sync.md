# 歌单自动同步功能

## 概述

导入的远程歌单（QQ音乐、网易云音乐、酷我音乐）现在会在用户查看时自动同步，无需手动点击同步按钮。

## 工作原理

### 按需同步策略

当用户请求歌单详情时（`GET /api/v1/music/playlists/{id}`），系统会：

1. **检查是否需要同步**
   - 本地歌单：不需要同步
   - 远程歌单：检查距离上次更新的时间间隔

2. **时间阈值判断**
   - 默认间隔：6小时
   - 如果距离上次更新 < 6小时：使用缓存数据
   - 如果距离上次更新 ≥ 6小时：自动触发同步

3. **自动同步**
   - 从远程平台拉取最新歌单信息
   - 更新歌单元数据（名称、封面、描述）
   - 更新歌曲列表
   - 更新 `updated_at` 时间戳

4. **容错处理**
   - 同步失败时自动降级，使用缓存数据
   - 不影响用户查看歌单
   - 错误信息记录到日志

## 配置选项

在 `application.yml` 中配置：

```yaml
app:
  playlist:
    auto-sync:
      # 是否启用自动同步（获取歌单详情时）
      enabled: true
      # 同步间隔（小时），距离上次更新超过此时间才会重新同步
      interval-hours: 6
```

### 环境变量

```bash
# 禁用自动同步
PLAYLIST_AUTO_SYNC_ENABLED=false

# 修改同步间隔为12小时
PLAYLIST_AUTO_SYNC_INTERVAL_HOURS=12
```

## 使用场景

### 场景1：用户导入歌单后立即查看
```
1. 用户通过 POST /api/v1/music/playlists/import 导入QQ音乐歌单
2. 立即调用 GET /api/v1/music/playlists/{id} 查看详情
3. 距离导入时间 < 6小时，使用已导入的数据，不触发同步
```

### 场景2：用户隔天再次查看歌单
```
1. 用户昨天导入了歌单（24小时前）
2. 今天调用 GET /api/v1/music/playlists/{id} 查看详情
3. 距离上次更新 > 6小时，自动触发同步
4. 返回最新的歌单数据
```

### 场景3：短时间内多次查看
```
1. 用户查看歌单（触发同步）
2. 5分钟后再次查看
3. 距离上次同步 < 6小时，直接返回缓存数据
4. 不会重复同步，节省资源
```

## 与手动同步的关系

- **手动同步接口**：`POST /api/v1/music/playlists/{id}/sync`
  - 仍然保留，用户可以随时手动触发同步
  - 不受时间间隔限制
  - 强制刷新歌单数据

- **自动同步**：`GET /api/v1/music/playlists/{id}`
  - 按需触发，节省资源
  - 受时间间隔限制
  - 对用户透明

## 性能影响

### 优势
1. **按需加载**：只在用户查看时才同步
2. **时间缓存**：避免短时间内重复同步
3. **异步体验**：用户感知不到同步过程
4. **容错降级**：同步失败不影响查看

### 注意事项
1. **首次请求可能较慢**：如果需要同步，响应时间会增加
2. **数据实时性**：最多延迟6小时（可配置）
3. **API调用开销**：会增加对第三方平台的API调用

## 最佳实践

### 推荐配置

**生产环境（高流量）**
```yaml
app:
  playlist:
    auto-sync:
      enabled: true
      interval-hours: 12  # 减少同步频率
```

**开发环境**
```yaml
app:
  playlist:
    auto-sync:
      enabled: true
      interval-hours: 1  # 更频繁同步，便于测试
```

**禁用自动同步**
```yaml
app:
  playlist:
    auto-sync:
      enabled: false  # 完全依赖手动同步
```

### 调优建议

1. **根据用户行为调整间隔**
   - 活跃用户多：增加间隔（12-24小时）
   - 用户少：减少间隔（3-6小时）

2. **监控第三方API限流**
   - 如果遇到限流，增加间隔时间
   - 或者禁用自动同步，只保留手动同步

3. **考虑时区因素**
   - 间隔时间基于服务器本地时间
   - 跨时区用户可能看到不同的同步行为

## 技术实现

### 核心代码位置

- **配置类**：`AppProperties.Playlist.AutoSync`
- **服务类**：`UserPlaylistService.autoSyncIfNeeded()`
- **调用点**：`UserPlaylistService.detail()`

### 数据库字段

使用 `user_playlists.updated_at` 字段判断是否需要同步：
- 导入时设置
- 每次同步时更新
- 比较当前时间与此字段的差值

## FAQ

**Q: 为什么不使用定时任务批量同步所有歌单？**
A: 按需同步更高效，只在用户查看时才同步，避免浪费资源同步从不查看的歌单。

**Q: 如果我想立即看到最新数据怎么办？**
A: 使用手动同步接口 `POST /api/v1/music/playlists/{id}/sync`。

**Q: 自动同步会影响API响应速度吗？**
A: 首次查看或超过间隔时间会触发同步，响应时间会增加。但大多数情况下使用缓存数据，响应很快。

**Q: 本地歌单会被自动同步吗？**
A: 不会。只有导入的远程歌单（QQ、网易、酷我）才会自动同步。

**Q: 可以针对不同用户设置不同的同步间隔吗？**
A: 目前是全局配置。如需个性化配置，需要扩展数据模型。
