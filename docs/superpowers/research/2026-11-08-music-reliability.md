# 音乐解析与播放可靠性优化

日期：2026-11-08。范围：后端及 DuckMusic 配套客户端。以本地实现和验证为交付范围，本轮没有修改发布版本。

## 录音身份与歌词

- `PlayInfo` 新增可选 `actualId`、`lyricMatch`；原始 `source/id` 继续用于用户收藏、歌单和历史，`actualSource/actualId` 指向实际音频。
- 跨源匹配保留 Live、Remix 等版本文字，要求歌手一致；已知时长允许差异为 2%（最少 2 秒、最多 5 秒）。不能确认真实录音的文本回退标记为 `unverified`。
- 缓存和合并中的播放响应保留录音身份；每个调用者获得独立响应，兼容音质别名不会相互覆盖 `requestedQuality`。
- App 按实际音源和 ID 请求歌词，并使用实际音源请求头；缓存旁文件与下载清单持久化身份。明确未验证的歌词、跨源但无实际 ID 的响应，以及身份未知的旧离线文件不加载同步歌词。
- App 的播放器和系统媒体信息优先使用音频实际时长，解析返回的实际时长作为备用值。下载解析使用 `prefetch=true`，不写入播放历史。

## 有界请求与缓存

- 歌词请求按来源和歌曲合并，所有上游阶段共用 8 秒预算；官方歌词失败退避 30 秒，全部失败短暂抑制 5 秒。普通/备用歌词缓存 10 分钟，逐字歌词缓存 6 小时；退避结束重新尝试官方接口。
- 酷我附加封面缓存限制为 10,000 条、6 小时；8 个工作线程、56 个待办位置。重复查询共享一次上游调用；每次查询连同排队最多 5 秒，列表补图最多等待 2 秒。
- 封面解析最多读取 8 KiB，拒绝不符合原酷我域名约束的结果；失败和超时不永久污染缓存，关闭时完成所有待办结果。
- 播放解析线程池为 8 个线程、16 个待办位置，拒绝时返回业务错误 `1013 / HTTP 503`；每个来源最多 4 个不同的未缓存解析。线程池满载不会让请求线程执行上游解析。
- 停止不再需要的解析时同时取消实际 HTTP 调用，并释放并发名额。
- 主动取消不会计为上游故障，不会污染失败缓存或 URL 可播放性缓存；被取消的半开探测只释放自己的名额。真正的上游超时仍执行原有故障退避。

## 播放历史

- 播放接口将历史交给后台单写入线程；最多保留 256 个不同的用户/歌曲待办，相同歌曲合并为最新快照。
- 临时失败最多尝试 3 次，重试保留原播放时间；数据库记录已有更新事件时不被旧事件覆盖。现有最近 100 首保留逻辑不变。
- 正常关闭停止接收新事件，在 5 秒内尽量排空已接收的事件，包括写入期间合并的新快照。
- 这是内存中的尽力写入队列，并非持久消息队列；进程异常退出或超过关闭等待时间可能丢失尚未完成的历史记录。

## 监控

复用现有 Micrometer/Actuator 配置，无数据库迁移：

- `music.requests`：按来源、操作和结果计数。
- `music.request.duration`：耗时及直方图。
- `music.cache.requests`：命中/未命中。
- `music.lyrics`：来源、提供方、行级/逐字粒度。
- `music.rejections`：过载和队列拒绝。

标签由有限白名单约束，不使用歌曲 ID、关键词、用户 ID 或 URL。上线后应观察分来源成功率、延迟、拒绝数量和歌词粒度，才能评价真实收益。
