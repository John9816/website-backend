# 汽水歌词与切歌并发优化

日期：2026-11-10，Asia/Shanghai。

## 复现与修复

上一轮已复用官方列表里的完整歌词和歌曲信息。本轮继续检查并发请求生命周期，发现四个具体问题：

- 下一首歌词已经预载时，切歌会先清理旧 effect，取消唯一订阅，播放器随后重新请求。现在按歌曲维护预载订阅，交接给当前歌曲时保留；跳到无关歌曲、换账号或卸载时取消不再需要的请求。省流量和慢网络继续跳过预载。
- 快速 A→B→A 切歌可能复用已取消但尚未从 map 清除的 A 请求。现在只复用有效请求，且已取消的播放或历史记录响应不能回填缓存。旧请求的 finally 只能删除自身，不能删除后来的请求。
- 歌曲详情请求较晚结束时，会覆盖期间已由搜索等列表写入的完整歌词快照。现在以原子 putIfAbsent 保留已存在的快照，当前等待者也直接拿到该快照；覆盖空歌词、旧歌词、异常 KRC 三种回归。
- 汽水播放地址仅需本地签名，却仍排在其他源的远程解析线程池中。现在使用调用线程生成票据，继续经过原解析流程，保留配置、预算、签名、缓存安全刷新、singleflight、限流及指标处理。

## 验证

后端测试先出现 5 项预期失败，再通过修复。完整 `mvn -q clean verify` 为 90 个测试套件、539 项测试，失败、错误和跳过均为 0。前端和 Node 服务端 `node --test tests/*.test.mjs server/*.test.mjs` 共 46 项通过。

受控浏览器夹具中，歌词请求耗时设为 800ms，预载 250ms 后切歌：旧版取消后重新发送，需再等约 815–820ms；修复后保留原请求，剩余等待约 550ms，歌词请求从 2 次降到 1 次。PC/H5 回归同时覆盖快速切歌、旧响应、账号切换、取消无关预载和省流量模式。

受控后端夹具中，阻塞共享解析执行器：旧版在 500ms 调用预算耗尽后超时；修复后本地票据在约 0–1ms 返回，且不占用远程解析队列。拒绝执行器、真实签名、音质、缓存刷新、禁用 primary 和耗尽预算均有回归覆盖。

以上耗时来自受控测试，不代表所有网络请求的生产延迟。发布后的真实接口、音频和 PC/H5 浏览器验证记录保存在服务器对应发布目录的 meta 中。
